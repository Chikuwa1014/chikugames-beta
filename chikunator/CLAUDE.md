# チクネーター

号口の `CLAUDE.md`（共通ルール）に従う。ここにはこのゲームだけの事実を書く。

## 1. 概要
思い浮かべた食べ物を、ちくわくんが質問で当てる推理ゲーム（20 の質問型）。β0.1.0（2026-11-04）最初の試作。
SEIJI の注文（2026-11-04）：「アキネーターのちくわ版」。見た目・キャラ・文言は既存のゲームに寄せず、ちくわ独自の「おでん鍋占い」にする（ちくわくんがおでん鍋の湯気を読んで当てる）。
質問に入る前に、うまそうなちくわの写真をランダムで 1 枚見せる（SEIJI の指示。5 枚の予定で、いまは 3 枚。残り 2 枚は SEIJI があとで送る）。

- 流れ：タイトル → ちくわの写真（`PHOTOS` からランダム）→ 質問 → 当てる → 勝ち／負け。
- 答え：はい（1）・たぶんそう（0.75）・わからない（数えない）・たぶん違う（0.25）・いいえ（0）。「ひとつ前にもどる」あり。
- 当てにいく：いちばんの候補の確率が `GUESS_P` をこえ、`MIN_Q` 問以上聞いたとき。または `MAX_Q`（20）問に達したとき。外れたらその候補をのぞいて続ける。
- 負け：リワード広告で「あと 5 問」（`CG.ad`。1 回だけ。いまは `?ad=test` のときだけ出る）。答えを教えてもらう（残りの候補から選ぶか、名前を書く）。

## 2. URL
`/chikunator/`。公開の状態：β公開（2026-11-05）。

## 3. コードの地図（`index.html` 1 ファイル）
| 名前 | 役割 |
|---|---|
| `PHOTOS` | 質問の前に見せるちくわの写真（`img/`。1200×675 の WebP） |
| `QS` | 質問（キーと文言）。キーは `FOODS` のタグに使う |
| `FOODS` | 食べ物（名前｜呼び方のちがい、絵文字、当てはまる質問のタグ。`~` は「ものによる」＝0.5、書かないタグは 0） |
| `build` | 表を作る。この端末で覚えたこと（`SAVE.learned`）を混ぜ、表に無い食べ物は足す |
| `like` / `recompute` | 答えのずれ（`SHARP`）から候補の確率を計算しなおす |
| `nextQuestion` | 答えたあとの迷い（エントロピー）がいちばん小さくなる質問。上位 3 つの近いものからランダム |
| `potSVG` / `setHeat` | おでん鍋とちくわくん。手ごたえで湯気とあわの勢いが変わる |
| `learn` / `teach` | 負けたとき・勝ったときの答え方を覚える（質問ごとに答えの合計と回数） |
| `window.CHIKU` | テスト用の公開 |

## 4. 保存キー
`chikunator-v1`：`{ plays, wins, loses, sound, learned: { 名前: { name, a: { 質問キー: [答えの合計, 回数] } } } }`。覚えるのは 200 件まで。

## 5. 調整用の数値
`index.html` の「調整用の数値」：`MAX_Q`・`AD_EXTRA`・`GUESS_P`・`MIN_Q`・`SHARP`・`LEARN_W`。

## 6. テスト
リポジトリ直下で `python3 -m http.server 8765` を起動し、`node chikunator/dev/test.cjs <保存先>`。
全部の食べ物を「正直なプレイヤー」で当てさせる（まちがいなし・8% まちがえる の 2 通り）。β0.1.0 では、まちがいなしで全部、まちがえありで 98% 以上当たり、平均 8 問ほど。
そのあと画面を通しで操作（写真・もどる・勝ち・負けて教える・覚えた食べ物が表に入る・`?ad=test` の広告ボタン）。

## 7. ゲーム固有の決まり
- 食べ物を足すときは、`dev/test.cjs` で当たる割合が下がっていないか確かめる。
- 覚えたことはこの端末だけ（サーバーへ送らない）。
- ちくわくんの左（穴のある側）から鍋へのびる茶色の1本は「触角」（もとは手のつもり。キモ可愛い。SEIJI の設定、2026-11-05）。消さない。頭の白いのは鉢巻。
