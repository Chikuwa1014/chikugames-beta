## 3. データの形（`js/data.js`）

下書きの `MZ.T`・`MZ.ITEMS`・`MZ.NODES`・`MZ.RECIPES`・`MZ.BUILDS`・`MZ.STAGES` の形はそのまま使う。直す点：

- 頭のコメントの「ちくわ開拓記」→「荒野開拓記（仮）」。`MZ.GAME`・`MZ.VERSION = 'β0.1.0'`・`MZ.SAVE_KEY = 'machizukuri-save'`・`MZ.SAVE_V = 1` はそのまま。
- `MZ.T.baseWater`・`baseFood` は **0** にする（要件は「家・水・食料のいちばん少ない数まで」。井戸も畑もなければ人は来ない）。キーは調整用に残す。
- `MZ.T` に足す：`radius: 0.35`（体の太さ）、`height: 1.7`（身長。目は `eye: 1.6`）、`fogStart: 45`・`fogEnd: 115`、`view3: { back: 4.5, up: 1.2 }`（三人称のカメラ）、`maxPeople: 60`（歩く姿の上限）、`autosave: 10`（秒）、`regrowCheck: 1`（また出るの判定の間かく秒）、`chunk: 120`（区画のマスの数＝240m）。
- 段階は 0 始まりの番号（0 開拓・1 集落・…）。`stage` が無い物は段階 0 から使える。

### 3.1 持ち物・道具
- `MZ.ITEMS`・`MZ.ITEM_ORDER`：下書きのまま（10 種。上限なし）。
- `MZ.TOOLS`：下書きのまま。道具は `{ axe: 1, pick: 1 }`（0 素手・1 さびた・2 石・3 鉄）で持つ。**持ちかえはしない**（たたく物に合う道具を自動で使う。斧・つるはしの段の高い方を常に使う）。

### 3.2 採れる物 `MZ.NODES`
下書きのまま（`need` は必要な道具の段）。速さは **1 回のたたきで減る量 = 1 + (道具の段 − need)**。`hp` が 0 になったら `drops` が入り、その物は消えて `back` 秒後にまた出る。
これで表のとおりになる：木・岩・粘土はさびた 1（おそい）・石 2（ふつう）・鉄 3（はやい）。鉄の鉱脈は石 1（おそい）・鉄 2（ふつう）。`tool` の無い草むら・石ころは素手でも 1 回で採れる。

### 3.3 レシピ `MZ.RECIPES`
- `ingot` の `at` を `'kiln'` → **`'furnace'`（炉）** に直す（要件：鉄インゴットは炉）。
- `axe3`・`pick3` に `stage: 1` を足す（鉄の道具は集落から）。
- 道具のレシピは、すでにその段以上を持っていたら「作った」と出して作れなくする。

### 3.4 建物 `MZ.BUILDS`
- **炉 `furnace` を足す**：`{ name: '炉', w: 1, solid: true, cost: { stone: 10, brick: 6, clay: 4 }, note: '鉄鉱石をとかして鉄インゴットにする' }`。かまどのれんがが先に要る順にする。
- `kiln` の note を「粘土を焼いてれんがにする」に。
- `lumber`・`bhouse` の `stage: 1` はそのまま（集落から）。
- 各建物に `jobs` を持てる形にする：`lumber` に `jobs: 2, makes: { log: 1 }, every: 20`（`MZ.T.lumber` は消して表へ移す）。
- `MZ.BUILD_ORDER = ['bench','road','house','field','well','fire','kiln','furnace','lumber','bhouse']`。
- 建物の表の意味：`w` 何マス四方か（正方形だけ。だから回しても使うマスは同じ）、`solid` 通れないか、`home` 住める人数、`water`・`food` まかなえる人数、`fixed` こわせない（小屋）。

### 3.5 区画とマス
- 1 マス 2m。区画は 120×120 マス（240m）。区画のキーは `"cx,cz"`（今回は `"0,0"` だけ）。区画 `"0,0"` の中心が世界の原点。マス `(gx,gz)`（0〜119）の中心の世界座標は `x = (gx − 60) * 2 + 1`。
- マスの持ち主は `Int32Array(120*120)` の表（0 は空き、ほかは建物の id）で持つ。保存はしない（読み込み時に建物から作り直す）。
- 採れる物の場所は **種（`MZ.T.seed` と区画のキー）から毎回同じに作る**（mulberry32 など）。保存するのは「消えている物の番号と残り秒」だけ。**数 `n` や並べ方を後で変えると古い保存の番号がずれる**ので、そのときは `SAVE_V` を上げて直す処理を書く（`CLAUDE.md` に書いておく）。配置はマスの中心に置き、小屋のまわり（`minR`）と土地の端 4m は避け、同じマスに 2 つ置かない。

### 3.6 保存データの形
`CG.save.wrap(data, MZ.SAVE_V)` の包み `{ game: 'machizukuri', v: 1, at, data }` を `CG.ls.setJSON('machizukuri-save', …)` で保存する。`data` は：

```js
{
  player: { x, z, yaw, pitch, view: 1 },        // view：1 一人称・3 三人称
  inv: { stick: 0, grass: 0, … },               // ITEM_ORDER の全部
  tools: { axe: 1, pick: 1 },
  pop: 0, stage: 0,                             // stage は届いた段階の最大（人が減っても下げない）
  timers: { migrate: 0, jobs: {} },             // jobs：建物 id → 次に作るまでの残り秒
  nextId: 2,
  chunks: {
    "0,0": {
      layers: {
        ground: [ { id: 1, t: 'hut', x: 59, z: 59, r: 0 }, … ],   // x,z は左上のマス、r は 0〜3（90 度ずつ）
        under: [],                                                // 地下の層（地下鉄。後の版）
        over: []                                                  // 高架の層（高速道路。後の版）
      },
      taken: { "12": 85.5, … }                                    // 消えている採れる物の番号 → また出るまでの残り秒（遊んでいない間は進まない）
    }
  }
}
```

読み込み：`v` が `MZ.SAVE_V` より新しい → 「新しい版のデータです。ページを読み直してください」と出し、上書きしない。古い → `MZ.migrate[v]` で 1 つずつ新しい形へ直す（今回は v1 だけなので空の表を用意しておく）。壊れている → さいしょからにしてお知らせを出す。

## 4. 大事な仕組みの決まり

### 4.1 採集
- ねらいの選び方（毎フレームではなく 0.1 秒ごとでよい）：主人公の位置から**水平距離 `T.reach` 以内**で、主人公の向き（yaw）と物への向きの cos が **`T.aimCos` 以上**の、出ている物の中から、**cos がいちばん大きい物**（同じぐらいなら近い方）を選ぶ。三人称でも主人公の位置と向きで選ぶ。`scene.pick` は使わない（数式で選ぶ）。
- 選んだ物の名前と動き（「木を切る」）と hp の残りを画面の真ん中の下に出す。採れないとき（道具の段が足りない）は「石のつるはしが必要」のように出し、ボタンは押せるが減らない。
- たたく：PC は E かマウス固定中の左クリック、スマホは右下の大きい「たたく」ボタン。**押している間は `T.hitCool` ごとにくり返す。** 一人称では右下に道具（斧かつるはし）を描いて振る（カメラの子。小さいローポリ）。
- 採れたら「＋3 原木」をお知らせに出す。

### 4.2 建築
- 「建てる」タブで建物をえらぶ → パネルを閉じて建築モード。足りない材料の物はえらべない（足りない物を赤で出す）。段階が足りない物は「集落（人口 10）で解放」と出してえらべない。
- 見本の場所：画面の真ん中から出した線と地面（y=0）の交わる点。`T.buildMax` より遠い・空を向いている → 水平に `T.buildMax` 先の点。その点を含むマスを、建物の中心がそこに来るように合わせる（w=2 は 2×2 マス）。
- 見本は同じ形のメッシュを半透明にして、置けるとき緑（`#5FBF5F`）、置けないとき赤（`#D9534F`）。
- 置けない条件：土地の外にはみ出す／建物のマスと重なる／**出ている採れる物と重なる**（消えている物のマスには置ける。置いたらその物はまた出ない）／主人公の体と重なる（`solid` の物だけ）。
- 回す：PC は R、スマホは「回す」。90 度ずつ（正面の向きが変わるだけ）。置く：PC は左クリックか E、スマホは「置く」。置いたあとも同じ建物の建築モードが続き（道を続けて置ける）、材料が足りなくなったら終わる。やめる：PC は Q か Esc か右クリック、スマホは「やめる」。
- こわす：「建てる」タブの「こわす」→ こわすモード。ねらった建物（見本の場所のマスの建物）を赤くし、「こわす」ボタン（PC は左クリック）で消す。材料は **`Math.floor(数 / 2)` もどる**。小屋はこわせない。
- 置く・こわすのたびに、マスの表・道のつながり・移住の上限を計算し直し、保存する。

### 4.3 移住者
- 道のつながり：小屋のマスに上下左右で接する道のマスから、道どうしを上下左右でたどる（幅優先）。たどれた道を「つながった道」とする。
- 家の数え方：家（`home` がある建物）のどこか 1 マスが、つながった道のマスに上下左右で接していれば数える（ななめは数えない）。
- 上限 = min(つながった家の `home` の合計, 井戸の `water` の合計 + `T.baseWater`, 畑の `food` の合計 + `T.baseFood`)。井戸・畑は道につながっていなくてよい。
- `T.migrate` 秒ごとに、人口が上限より少なければ 1 人ふえる（来たら「1 人移住してきた（人口 5）」）。多ければ 1 人ずつ減る（こわしたとき）。
- HUD に「人口 4／上限 4　家 4・水 10・食料 4」と出し、**いちばん少ない物を色で目立たせる**。家がつながっていないときは「道が小屋とつながっていない家がある」と出す。
- 住民の姿：歩く姿は `min(人口, T.maxPeople)` 人。それぞれ住む家を 1 つ決め、その家のまわり 3〜8m をゆっくり歩き、ときどき止まる。建物・土地の外には入らない（ざっとでよい）。thin instance を毎フレーム更新する。

### 4.4 住民の仕事・段階
- 人口を、`jobs` がある建物へ建てた順に割り当てる（1 つに `jobs` 人。足りなければその建物は止まる）。家に住む人と働く人は別に数えない（人口の中から働く）。
- 動いている建物は `every` 秒ごとに `makes` を持ち物へ入れる（「きこり小屋：＋1 原木」は 1 分に 1 回だけお知らせに出す）。止まっている建物はパネルの「建てる」タブで「人が足りず止まっている」と出す。
- 段階：人口が `MZ.STAGES[i].pop` 以上になったら `stage = max(stage, i)`。上がったら大きく「集落になった！ きこり小屋・れんがの家・鉄の道具が作れる」と出す。今回は段階 1（集落）まで中身がある。

### 4.5 つぎの目標
上から順に見て、**最初に満たしていない 1 行**を HUD の上に出す（`ui.js` の表 `MZ.GOALS = [{ done: s => …, text: '…' }]` で持つ）：
1. 草むらから草を 3 つ集めよう → 2. ロープを作ろう（パネル → 材料） → 3. 木を切って原木を 4 つ集めよう → 4. 石を 2 つ集めて、作業台を建てよう → 5. 作業台の近くで石のつるはしを作ろう → 6. 小屋から土の道をのばそう → 7. 板を作って、道に面した所に木の家を建てよう → 8. 井戸を建てよう → 9. 畑をつくろう → 10. 移住者を待とう（家・水・食料のいちばん少ない数まで来る） → 11. 粘土を掘ってかまどを建てよう → 12. れんがを作って炉を建てよう → 13. 鉄の鉱脈を掘って鉄インゴットを作ろう → 14. 人口 10 で集落にしよう（家・井戸・畑をふやす） → 15. きこり小屋を建てよう → 16. 鉄の道具をそろえよう → 17. 「ここまでが今の版です。れんがの家で人口をふやそう」。
すでに満たしている（例：道具を先に作った）物は飛ばす。

### 4.6 パネル
- PC は Tab か I、スマホは右上の「持ち物」ボタンで開閉。タブは「持ち物」「材料」「道具」「建てる」。
- **縦持ち（`(orientation: portrait)`）は画面の下半分、横持ちは画面の右側（幅 min(46vw, 420px)、上下いっぱい）**。CSS のメディアクエリで切り替える。ゲームの画面は見えたまま。
- 開いている間は歩く・見回す・たたくを止める（世界の時間：移住・仕事・また出るは進める）。マウス固定は外す。
- レシピの行：名前・材料（持っている数／要る数、足りない物は赤）・設備（「作業台の近くで」。近くにないと押せない）・作るボタン。設備の近さは主人公から `T.near` m 以内にその建物があるか。

### 4.7 一人称／三人称
- 一人称：カメラは目の高さ（`T.eye`）。主人公の体は描かない。
- 三人称：カメラは主人公の後ろ `view3.back` m・頭の上 `view3.up` m で、同じ yaw・pitch で見る。主人公の姿を描き、歩くと手足を振る（部品ごとに回す。主人公だけは thin instance でなくふつうのメッシュでよい）。カメラと主人公の間に建物があれば、カメラを主人公に寄せる（線とマスの表でざっと判定）。
- 切り替え：PC は V、スマホは右上の「視点」ボタン。保存に入れる。

### 4.8 モデル（`models.js`）
- 登録の仕組み：`MZ.models = { tree: () => mesh, … }`（種類の名前 → 元のメッシュを作る関数）と `MZ.getModel(key)`（1 回だけ作って使い回す）。ゲーム側は `getModel` だけを使い、**作り方（コードか glTF か）を知らない**。glTF に変えるときは関数の中身を差し替えるだけにする。どのモデルも「足もとが y=0、建物の中心が原点、正面は −z、1 単位 = 1m」をそろえる（ファイルの頭のコメントに書く）。
- 描く呼び出しを減らすため、**部品ごとの色は頂点カラーに入れ、材質は全体で 1 つ**（`StandardMaterial`、`specularColor` 黒）にして `MergeMeshes`（multiMaterial なし）する。下書きの `mat()` 方式から直す。
- 下書きから直す物：`player`（ちくわくんの円柱）と `person` は**人間の形**にする（身長 1.7m：脚・胴・腕・頭・髪。主人公は作業着の茶・紺、住民は服の色を数種）。主人公は手足を動かすので部品を分けた `TransformNode` で作る。`hut`・`house` は 2×2 マス（4m）に収まる大きさのまま、色を落ち着いた自然な色に（窓の水色は暗めのガラス色 `#6F8A96` など）。**炉 `furnace` を足す**（れんが積みの四角い炉と煙突、口の中が暗い赤）。斧・つるはしの手持ちモデル（4.1）を足す。
- 木は 2 種類ぐらいの形をまぜ、配置のときに大きさ 0.85〜1.2 倍・向きをばらばらにする（thin instance の行列で）。

## 5. 性能の決まり

- 採れる物（数百）は種類ごとに **thin instance**（`thinInstanceSetBuffer`）。消えた物は行列を大きさ 0 にして `thinInstanceBufferUpdated`。建物は種類ごとに `createInstance`（数が少ない）でもよい。住民は person の thin instance を毎フレーム更新。
- 霧は `FOGMODE_LINEAR`（`fogStart`〜`fogEnd`）、空の色（`clearColor`）と霧の色を同じに。`camera.maxZ = fogEnd + 10`。
- 歩く姿の住民は 60 人まで（`T.maxPeople`）。人口の数字はそれより多くてよい。
- **影は付けない**（ShadowGenerator を使わない）。光は HemisphericLight と DirectionalLight 1 つずつ。
- `engine.setHardwareScalingLevel(1 / Math.min(devicePixelRatio || 1, 1.5))`（`kenkyujo` と同じ）。地面は 1 枚（大きいマスの頂点カラーで土の色むら）。動かない物の `freezeWorldMatrix()`、材質の `freeze()`、`scene.skipPointerMovePicking = true`。
- 当たり判定は Babylon の物理や `moveWithCollisions` を使わず、**マスの表（`solid` の建物）と、`r > 0` の採れる物の円**で 2D の押し返しを書く（体の半径 `T.radius`）。土地の端は ±(120 − 0.5)m で止める。
- 目標：スマホ 30fps・PC 60fps（ヘッドレスでは測れないので、測るのは本物の端末で。手元では描く呼び出しの数を見る）。
