## 区切り 3：土地を広げる（要件 3.4・5 章）

### 3.1 データ（`js/data.js`）

| 物 | 決まり |
|---|---|
| 区画の種類 `MZ.CHUNK_KINDS` | 場所から毎回同じに決めるため、表で持つ：`'0,1'` 森・`'1,0'` 岩場・`'0,-1'` 粘土の土地・`'-1,0'` 森・`'1,1'` 岩場・`'1,-1'` 粘土の土地・`'-1,-1'` 岩場・`'-1,1'` 粘土の土地。`'0,0'` は「もとの土地」（今のまま）。北は +z、東は +x（仕事場タブの向きと同じ） |
| 種類の中身 `MZ.KINDS` | `forest: { name: '森', mult: { tree: 2 } }`・`rocky: { name: '岩場', mult: { rock: 3, iron: 3 } }`・`clayland: { name: '粘土の土地', mult: { clay: 3 } }`。採れる物の数は `NODES[k].n × mult[k]`（無ければ 1） |
| 広げる材料 `MZ.LAND_COST` | 持っている区画の数で決める表。`[{ upto: 2, cost: { plank: 40, stone: 40, rope: 5 } }, { upto: 4, cost: { plank: 80, stone: 80, brick: 40 } }, { upto: 8, cost: { plank: 120, stone: 120, brick: 80, ingot: 10 } }]`。n 区画め（もとの区画は数えない。広げる 1 回めが 1）は、`upto` が n 以上の最初の行 |
| 条件 | 段階が `T.villageStage` 以上 |

### 3.2 広げる（`world.js`・`town.js`）

- `MZ.canExpand(cx, cz)` → 理由の文（広げられるなら空）。理由は次のどれか：「世界の外」（cx・cz が −1〜1 の外）、「もう持っている」、「となりの区画を先に」（持っている区画と上下左右でとなり合っていない）、「村（人口 50）で解放」、「材料が足りない」。
- `MZ.expand(cx, cz)` → true／false。中でする順番：
  1. 材料を払う。
  2. `state.land` の後ろにキーを足し、`state.chunks[key] = { layers: { ground: [], under: [], over: [] }, taken: {} }` を作る。
  3. `W.setLand(state.land)`。
  4. `W.buildChunkNodes(key)`（種類の `mult` を使う。**区画 "0,0" は今の数のまま**）。
  5. 採れる物の描画を作り直す（3.3）。
  6. `W.applyTaken()`。
  7. 草の密度（その区画のマスだけ `cellDens`）。
  8. 塗り分けの表（その区画のマスだけ）。
  9. 柵・外の起伏・山・柵の外の飾りを作り直す（3.4）。
  10. 保存する。お知らせ「土地を広げた（岩場）」。
- `buildChunkNodes` の中で、物ごとの `nd.tk` を付けておく（区切り 1 のレビューの指摘。`state.chunks[key]` があればその `taken`、無ければ空の物）。`W.nodeActive`・`W.takenOf`・`W.take` は、`nd.tk` が無くても例外にしない（`!nd.tk` は「出ている」）。
- 起動のとき（保存から）も同じ形で、`state.land` のすべての区画を作る（今の `W.buildNodes(landKeys)` のまま。`mult` を使う）。

### 3.3 採れる物の描画の作り直し（`gfx/nodes.js`）

- 入れ物（`makeForm` の固定の `Float32Array`）は、種類の全部の数で作っているので、物が増えたら作り直す。`G.nodes.rebuild(nodes)` を作る：今の入れ物（メッシュ・バッファ）を片づけてから `init` と同じに作り、今の画質の `apply` をやり直す。片づけで材質・写真は捨てない（使い回す）。
- 飾り（倒木・枯れ枝・小石）は区画ごとに作る。種は `T.seed + 77` と区画のキー。**区画 "0,0" は今の乱数の順のまま**（`r()` の回数を変えない）。ほかの区画は、"0,0" と同じ数・同じ決まり（区画の中の 3〜116 のマス・採れる物のマスをよける）で作る。
  - 今の `layout` は、小石を「一覧の先頭から `q.pebbles` 個」だけ見ているので、足した区画の小石が出ない。区画ごとの一覧にして、主人公の近くの区画から順に、距離の内の物を入れ物の数まで入れる形にする。
- 並べ直しの重さ：物が 9 区画で約 4,000 個になる。並べ直し（4m 動いたとき）で全部の物の距離を見るのはよい（0.25 秒に 1 回まで）。毎フレームは見ない。

### 4.2 建物の 3 段と近く用の数の上限（`gfx/looks.js`）

今の「近く用のメッシュに `addLODLevel` で遠く用をつなぐ」形では、近く用の数に上限を付けられない。次の形に変える。

- `put` は、遠く用（無ければコードの形）のインスタンスをいつも置く。遠く用に `addLODLevel(xfarDist, 最遠)`・`addLODLevel(bldFar, null)` を付ける。最遠が無い種類は遠く用をそのまま使う（`BUILD_MODELS` の `xfar` に遠く用の名前を書く）。
- 近く用は「近くの建物の係」が受け持つ：0.5 秒に 1 回、主人公から `houseNear`（`BUILD_MODELS` の `lod` があればその距離）以内の建物を近い順に並べ、上位 `nearMax` 軒だけに近く用のインスタンスを置く。その建物の遠く用は隠す。はずれた建物は近く用を片づけ、遠く用をもどす。入れかえは 1 回に 2 軒まで（ちらつきとかたまりを防ぐ）。
- 低：近く用は使わない。最遠か、コードの形（GLB が読めないとき）。
- 置いた建物のインスタンスには `freezeWorldMatrix()` を付ける（動かないので）。置き直し（画質を変えたとき）のときは作り直す。
- `G.tris()` は今のまま（インスタンスごとに、いま選ばれている LOD を数える）。

### 4.4 上限をこえたとき（`G.budgetTick`）

2 秒ごとに数え、上限をこえていれば、次の順に 1 段ずつ下げる（1 回に 1 段）：

1. 草を 10% へらす（今の最小 0.1 まで）。

3. 木の近く用の距離（`treeLod[0]`）を 0.85 倍ずつ縮める（今の 60% まで）。
