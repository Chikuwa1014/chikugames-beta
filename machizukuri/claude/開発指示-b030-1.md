## 0. 目的と方針

- **見た目と遊びは 1 つも変えない。** 変えるのは「区画 "0,0" の 120×120 マスだけ」を前提にしている所。マスの表・当たり・道のつながり・採れる物の番号・保存の形を、**最初から 9 区画（3×3、360×360 マス）の世界**で持つ形に直す。
- この区切りで持っている土地は **"0,0" だけ**。次のものは入れない：土地を広げる仕組み・土地タブ・区画の種類（区切り 3）、新しい建物・店・自動の上限・工房（区切り 2）。ただし、区切り 2・3 で作りかえ直さずに済むよう、保存の形と関数の形はここで決める（4 章・8 章）。
- **やり直しが利くよう、作業の前に今の姿を撮っておく**（7.1）。比べる相手は、直す前の作業ツリー（β0.2.0、コミット `64d8442`）。
- 1 つ終わるごとに `node machizukuri/dev/test.cjs 1`（いちばん速い区切り）を通す。全部が終わったら 1〜4 を全部通す。
- 決められないことは仮に決めて進め、報告に書く（止まらない）。

## 1. 座標の決まり（全体のマス）

| 名前 | 中身 |
|---|---|
| 区画 | 120×120 マス（240m）。キーは `"cx,cz"`。この版は `cx`・`cz` が −1〜1 の 9 つだけ（最初の区画 "0,0" が真ん中） |
| 全体のマス `(gx, gz)` | **区画 "0,0" の中のマスの番号と同じ数**になるように取る。範囲は −120〜239（3 区画ぶん、360 マス）。区画 (cx,cz) のマスは `gx = cx*120 + lx`（`lx` は区画の中の番号 0〜119） |
| 世界の座標 | 今と同じ。`MZ.cellOf(v) = floor(v/2) + 60`、`MZ.cellPos(g) = (g − 60)*2 + 1`（式は変えない。負のマスでもそのまま使える） |
| 表の番号 | `MZ.ci(gx, gz) = (gz + 120) * 360 + (gx + 120)`。世界の外は −1 |

こう取ると、`MZ.place('house', 80, 70)` や `MZ.cellPos(gx)` のような今の呼び方（テストを含む）は、区画 "0,0" の中ならそのまま同じ意味になる。**`gz * 120 + gx` の形で表を引いている所は全部 `MZ.ci` に置きかえる**（2 章の一覧）。

`js/data.js` に足す定数（`MZ.T` の中）：

```js
span: 3,   // 世界の幅（区画の数）。真ん中が "0,0"。全体のマスは 360×360
```

`world.js` で次を作る（ほかのファイルはこれだけを使い、120 や 360 を直接書かない）：

```js
MZ.GN = T.chunk * T.span;            // 360：全体のマスの一辺
MZ.G0 = -T.chunk * (T.span - 1) / 2; // -120：全体のいちばん小さいマスの番号
MZ.ci = (gx, gz) => …;               // 表の番号。世界の外は -1
MZ.inWorld = (gx, gz) => …;
MZ.chunkKey = (cx, cz) => cx + ',' + cz;
MZ.chunkOfCell = (gx, gz) => ({ cx, cz, key, lx, lz });   // floor で割る（負に注意：Math.floor(gx / 120)）
MZ.landAt = (gx, gz) => …;           // 持っている区画のマスか（W.land の 9 マスの表を引くだけ。毎回文字列を作らない）
MZ.landAtPoint = (x, z) => …;        // 世界の座標で
MZ.chunk = (key = '0,0') => MZ.state.chunks[key];   // 引数なしは今までどおり "0,0"（テストが使っている）
```

- `W.land = new Uint8Array(9)`（番号 `(cz+1)*3 + (cx+1)`）。`W.setLand(keys)` で書く。`landAt` は割り算 2 回と表 1 回だけにする（草の並べ直しで 1 回に数千回呼ぶため）。
- `T.half`（120）は「1 区画の半分の長さ」の意味だけに残す。**土地の端としては使わない**（土地の端は `landAt` か、下の `W.inLand`・`W.clampLand` で決める）。

#### 2.1.1 区画ごとの採れる物（番号を守る）

- 区画 `key = "cx,cz"` の乱数は、今と同じく `mulberry32((T.seed ^ hashStr(key)) >>> 0)`。`"0,0"` の乱数の呼び方・回数・順番は 1 つも変えない（`VARIANTS` の `rng()` も含む）。**`dev/test.cjs` の「配置が変わっていない」（`79e4b006:444`）がそのまま通ること。**
- 区画の中のマス `lx, lz`（`lo = 3`〜`hi = 117`）を今と同じ式で引き、置く場所は `gx = cx*120 + lx`、`x = MZ.cellPos(gx)`。区画 "0,0" では `gx = lx` なので今と同じ。
- 小屋のマスをよける処理（59〜60）は区画 "0,0" だけで行う。`minR`（小屋からの距離）は今と同じ `Math.hypot(x, z)`（世界の座標）で比べる（ほかの区画ではいつも遠いので、結果は変わらない）。`used` の表は区画ごとの 120×120 でよい（今と同じ）。
- 物に足す欄：`ck`（区画のキー）、`li`（区画の中の番号。0 から）。`gx`・`gz` は全体のマス。`idx` は今までどおり `W.nodes` の通し番号（描画の入れ物の番号に使う）。区画 "0,0" を最初に作るので、"0,0" では `li === idx`。
- `W.byChunk = { "0,0": [全体の番号…] }` を作る。
- 種類ごとの組（`W.groups`・`groups[k + vi]`）は全部の区画で共通にする。区画ごとの作業の外で、最初に 1 回だけ作る（今は種類のループの中で作っている。作る順と中身は今と同じにする）。
- `MZ.gfx.nodes.init(W.nodes)` は、全部の区画を作り終えてから 1 回だけ呼ぶ。
- 区切り 3 では、広げたときに新しい区画の物を `W.nodes` の後ろに足して `nodes.init` をやり直す。そのために「区画 1 つ分を作る関数」`buildChunkNodes(key)` を分けておく（中で `nodes.init` を呼ばない）。

#### 2.1.2 `main.js` の呼ぶ順

`W.buildNodes()` は今 `MZ.state = state` より前に呼ばれている。持っている区画の一覧が要るので、`W.setLand(state.land); W.buildNodes(state.land);` の形にし、`state` を引数で渡す（`MZ.state` を前へ動かさない。`setQuality` の中の並べ直しが `MZ.state` の有る無しを見ているため）。

### 2.4 `js/save.js`（4 章も読む）

- `MZ.newState()`：`land: ['0,0']` を足す。ほかは今のまま。
- `MZ.migrate[1] = d => …`（版 1 → 版 2）：
  - 深い写しを作って直す（元の物を書きかえない）。
  - `land = ['0,0']` を足す。`chunks` は `"0,0"` だけを残す（版 1 にはほかの区画は無いはずだが、あれば捨てる）。`chunks["0,0"]` が無ければそのまま返す（`normalize` が壊れている扱いにする）。
  - 建物の座標・`taken` の番号・`timers`・`nextId` は**触らない**（区画 "0,0" の中の座標と番号は、版 2 でも同じ意味）。
- `normalize(d)` を全区画の形に書きかえる（順番もこのとおりに）：
  1. `land`：配列でなければ壊れている扱い。`/^-?\d+,-?\d+$/` で、`cx`・`cz` が −1〜1 の物だけ残し、重なりを除く。**`"0,0"` が無ければ壊れている扱い**（`null`）。`"0,0"` を先頭にして並べる。
  2. `chunks`：`land` に無い区画のデータは捨てる。`land` にあって `chunks` に無い区画は空（`{ layers: { ground: [], under: [], over: [] }, taken: {} }`）で作る。`"0,0"` の `ground` が配列でなければ壊れている扱い（今と同じ）。
  3. 建物：全体の `used`（`Uint8Array(GN*GN)`、読み込むとき 1 回だけ作る。約 130KB）と全体の `ids` で調べる。**小屋を先に調べる**（未実装タスクの保留「小屋より前に重なる建物があると小屋が捨てられる」を片づける。小屋は "0,0" にしか無い）。そのあと区画の順・配列の順に調べる。捨てる物：知らない種類・`id`・`x`・`z` が整数でない・`id` の重なり・**`x`・`z` が 0〜119 の外**（左上のマスは自分の区画の中）・使うマスのどれかが持っている土地の外・重なり。残す欄は `id・t・x・z・r` と、**`mk`（区切り 2 の工房のえらび。文字列で `MZ.ITEMS` にある物だけ。無ければ書かない）**。
  4. 小屋が 1 つも無ければ壊れている扱い（今と同じ）。
  5. 主人公の場所：数でなければ壊れている扱い（今と同じ）。数なら `W.clampLand` と同じ考えで「持っている区画の四角を 0.5 内へ寄せた四角」のいちばん近い点へ収める（`save.js` は `world.js` より前に読まれるので、ここに小さい関数を書く。`land` から求める）。"0,0" だけなら ±119.5（今のテストと同じ値）。
  6. `taken`：区画ごとに、値が数のキーだけ残す（番号の範囲は `W.applyTaken` が見る。今と同じ分担）。
  7. `nextId`：今と同じ（全区画の `id` の最大 + 1 以上）。
  - 今の `normalize` にある、ほかの欄の直し（`inv`・`tools`・`pop`・`stage`・`timers`）はそのまま残す。
- `MZ.loadSave`・`MZ.saveNow`：変えない（`SAVE_V` を 2 にすれば、版 1 は `migrate[1]` を通る。版 2 より新しい物は今までどおり「新しい版のデータです」で読まず、上書きもしない）。

### 2.5 `js/gfx/ground.js`（塗り分けの表）

- `mark.data` を `Uint8Array(GN*GN*4)`（518,400 バイト）に、`RawTexture` を `GN × GN` にする（線形補間・CLAMP・ミップマップなしは今のまま。WebGL1 でも 2 のべき乗でなくてよい形）。
- `cellKind(gx, gz)`：世界の外なら 0。`MZ.world.owner[MZ.ci(gx, gz)]`。
- `writeCell`：書く場所は `MZ.ci(gx, gz) * 4`。
- `markBuilding(b)`：まわり 2 マスの範囲を `MZ.town.gpos(b)` から求め、世界の外は飛ばす。
- `markAll()`：**持っている区画のマスだけ**を回す（持っていない区画は 0 のまま。回すマスの数は今と同じ 14,400）。`tex.update` は 1 回だけ。
- シェーダー：`(wp + 120.0) / 240.0` と `abs(wp) >= 120.0` を、JS の値（`-MZ.G0 * T.cell` = 240、`MZ.GN * T.cell` = 720）を文字列に入れて `(wp + 240.0) / 720.0` と `abs(wp) >= 240.0` にする（数を直書きしない）。1 画素が 1 マス（2m）なのは今と同じなので、区画 "0,0" の中の見え方は変わらない。
  - 変わるのは柵ぎわの 1m だけ：今は表の外を CLAMP で端の色をのばしていたのが、となりの区画（0）と混ざる。土地の端のマスに道や畑を置いたときに、塗りが半マスぶん細く見えるだけなので、そのままでよい（報告に書く）。
  - 精度：地面の材質は Babylon の PBR（`precision highp float`）。720m を 360 画素で引いても足りる。念のため、スマホの `mediump` だけの端末では 1 画素の 1/4 ほどずれるおそれがある、と頭のコメントに書く。
- **起伏・山なみ・柵の外の飾り・柵（`hOut`・`coords`・`buildTerrain`・`buildMountains`・`buildOutskirts`・`buildFence`）は、この区切りでは触らない**（`HALF` は「最初の区画の半分」の意味として残す）。持っている土地に合わせて作り直すのは区切り 3。そのため頭のコメントに「区切り 3 で持っている土地の四角から作り直す」と 1 行書く。

### 2.6 `js/gfx/grass.js`

- `S.dens`・`S.dn` を `Float32Array(GN*GN)`（2 つで約 1MB）に。
- `cellDens(gx, gz)`：番号は `MZ.ci`。式（`MZ.cellPos` から作るノイズ）は今のまま。
- `densAll()`・`densOwner()`：**持っている区画のマスだけ**を回す（回す数は今と同じ。`densOwner` は建てる・こわすたびに呼ばれるので、全体の 129,600 マスを回さない）。持っていない区画の密度は 0 のまま。
- `layout(px, pz)`：`x <= -lim …` の判定を、世界の外（±`-G0*C` などの値）かどうかに置きかえ、番号は `MZ.ci(Math.floor(x / C) + N / 2, …)`。持っていない区画のマスは密度 0 なので、そこで飛ばされる。**今は土地の外の点を「密度を見る前」に飛ばしているが、密度 0 で飛ばしても、置かれる株と株の順は同じになる**（`hash3` は位置だけから取るので）。株の数・並びが前と同じことをテストで確かめる（7.2）。
